## One clarification up front

Flow A is **not** the GitHub auto-commit configuration. The naming in `docs/Initial_use_cases.md` is:

- **Step 1 — GitHub-side configuration.** Rulesets, canonical `ci / Test and build` check, Dependabot
  `groups:`, `claude-review` scoped away from bot PRs. Done, and that is the piece already completed.
- **Flow A — deterministic PR triage.** GitHub API + policy only, no clone, no model, no local gates.
  Also **done** (PR #14, `2a22858`), with acting operations gated behind `pr-triage --apply`.
- **Flow B — code remediation.** CodeQL findings (case 3) and security alerts with no PR (case 4).
  Clone → architect/critic → engineer patch → local gates → review → push → PR → CI monitor.

So Flow A is finished, not just configured. **Flow B is the open work**, and it is roughly half built:
the reasoning and testing machinery exists, the publishing half does not.

   `_notify` stops returning `unconfigured`.

   against `{approve, remediate, escalate, decline}`; an unrecognised value blocks the plan rather
   than skipping the item. **Write into the existing `latest-escalations.json`** (`triage.py:922-931`)

   --note`. This is what makes decision 3 — *escalate before coding* — real rather than aspirational.
4. **Honour `policy` (B3).** At minimum `address_severities` (planning-time filter, so the audit

   not `--filter`), engineer commits into it, purged at terminal state with an age-based sweep. The

6. **Gate isolation (B8).** Privilege separation inside the test stage: gate subprocesses under a
   second unprivileged UID, state dir `0700` owned by the stage UID, workspace owned by the gate UID,
   egress denied for the gate UID. **Redact `GITHUB_TOKEN_FILE` from the gate environment in the same
   change** — `_gate_environment` (`testing.py:198-203`) currently strips three token env vars and
